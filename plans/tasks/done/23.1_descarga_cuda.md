# 23.1 · Descarga del backend CUDA desde la app

**Estado:** ✅ Terminada
**Tarea padre:** [23 · Calidad y aceptación](23_calidad_aceptacion.md)
**Origen:** paso 5 de la 23, criterio §9 "CUDA automático con NVIDIA". El instalador no trae CUDA (D2 = descargable) y la descarga que faltaba es el paso 6.4 de la 05.
**Doc:** §2.1, §9

## Objetivo
Con una GPU NVIDIA, la app instalada ofrece descargar el paquete CUDA de whisper.cpp. Al terminar lo usa sin reiniciar, y si falla vuelve a CPU igual que ahora.

## Pasos

### Paso 1 — Ubicación del paquete descargado
- [x] `engine/paths.ts`: añadir `downloadedBinRoot()` = `userData/backends`. `whisperCliPath(backend)` busca primero en `resources/bin/<backend>` y después en `userData/backends/<backend>`, así dev sigue usando `resources/bin/cuda`
- [x] `installedBackends()` tiene en cuenta las dos raíces
- [x] `engine/backend.ts`: `BackendInfo` gana `nvidia: boolean` (hay hardware NVIDIA aunque CUDA no esté instalado) y `cudaDownloadable: boolean` (NVIDIA presente, sin CUDA y app empaquetada)
- [x] `resetDetection()` para repetir la detección después de instalar o borrar CUDA sin reiniciar la app
- [x] **Bug visto en la 23:** `detect()` solo repite la detección si el backend guardado desaparece, no si aparece uno mejor. Si arrancó una vez sin CUDA (`detectedBackend = cpu`) y después CUDA se instala, se queda en `cpu` para siempre. Guardar `installedBackends` en settings y volver a detectar cuando cambien

### Paso 2 — Servicio de descarga (`services/cudaPackage.ts`)
- [x] Constantes: release `b5130`, asset `whisper-cublas-12.4.0-bin-x64.zip` y tamaño esperado (el mismo que fija `scripts/fetch-binaries.mjs`; sacarlo a `src/shared/whisper.ts` para no duplicarlo)
- [x] Descargar a `userData/backends/cuda.zip` con `downloadWithResume()` (`modelDownload.ts`): progreso, reanudar, cancelar y comprobar el espacio libre antes (~2 GB entre el zip y lo descomprimido)
- [x] Descomprimir en `userData/backends/cuda.tmp/` con el `tar.exe` que trae Windows (`tar -xf`), sin módulos nativos
- [x] Copiar el runtime de Visual C++ (`msvcp140`, `vcruntime140`, `vcruntime140_1`, `vcomp140`) desde `binRoot()/cpu`
- [x] Validar con `probeBackend('cuda')` sobre la carpeta temporal (debe decir `found N CUDA devices`). Si falla: borrar y devolver el error
- [x] Renombrar `cuda.tmp` → `cuda` (atómico), borrar el zip, `resetDetection()` y guardar `detectedBackend = cuda`
- [x] `removeCudaPackage()`: borra `userData/backends/cuda` (con cerrojo si hay una transcripción usándolo) y repite la detección

## Bitácora
- 2026-09-28 — Creada al revisar la 23. El usuario eligió descargarlo desde la app frente a meterlo en el instalador (~600–700 MB) o dejar la v1 solo con CPU. Se descarga el zip oficial de GitHub, sin hosting propio.
- 2026-09-28 — **Detección obsoleta (bug encontrado en la 23):** antes solo se volvía a detectar si el backend detectado desaparecía, así que un CUDA añadido después nunca se usaba (esta PC tenía `backend: cpu, detectedBackend: cpu` con CUDA instalado). Ahora settings guarda `installedBackends` y se vuelve a detectar si cambia (`engine/detection.ts`, con tests). Si el elegido coincidía con el detectado anterior se toma como "automático" y sigue al nuevo (`followDetected`); si el usuario eligió otro, se respeta. No hace falta migración: las claves que faltan toman el valor por defecto y fuerzan una detección.
- 2026-09-28 — **Diseño:** release, asset, tamaño y sha256 viven en `src/shared/whisperRelease.json`, que leen tanto la app como `scripts/fetch-binaries.mjs` (una sola fuente). Se añadió comprobación sha256 además del tamaño. Se extrae con el `tar.exe` de System32 (sin módulos nativos); el paquete se arma en `backends/cuda.tmp`, se valida con `whisper-cli --help` (debe ver la GPU) y solo entonces se renombra a `backends/cuda`. El zip se borra siempre tras intentar instalar (si la validación falla, reintentar con el mismo no sirve y ocupa ~650 MB). El runtime VC++ se copia de `resources/bin/cpu`. La lista de DLL excluidas está duplicada con el script de binarios (anotado en el código).
- 2026-09-28 — **Desviaciones:** `cudaDownloadable` no exige `app.isPackaged`, para poder probar el flujo en dev. Tras instalar se pone `backend: 'cuda'` y se vuelve a detectar, en vez de escribir `detectedBackend` a mano. Se añadieron un IPC `backend:cuda-status` y un evento `backend:changed` que no estaban en el plan (la UI necesita saber si hay `.part` y enterarse de los cambios de backend). Los errores se muestran como toast, igual que en los modelos; `DownloadProgress` se sacó a su propio componente para reutilizarlo.
- 2026-09-28 — **Verificación real** (script de prueba con los módulos de la app, fuera del repo): se descargó el zip oficial de GitHub (674 MB, ~53 MB/s), se canceló a ~68 MB y se reanudó hasta el final con el `.part`. Con `CUDA_VISIBLE_DEVICES=-1` la validación dio `cudaInvalid` y no quedaron ni `backends/cuda`, ni `.tmp`, ni zip. Con la GPU visible se instaló (`found 1 CUDA devices`, 23 archivos). Después se copió a `%APPDATA%\RebeccaWritesackends\cuda`, se ocultó `resources/bin/cuda` y se lanzó `npm run dev` con los settings obsoletos (`cpu/cpu`): el log dio `Backend detectado: cuda … instalados: cuda, cpu, NVIDIA: true` y settings pasó a `cuda/cuda`. Al quitar el paquete y relanzar: `detectado cpu, instalados: cpu, NVIDIA: true`. **No verificado aquí** (hace falta hacer clic en la app instalada): la tarjeta, el toast de aviso, los botones Descargar/Cancelar/Quitar y una transcripción real con CUDA desde `userData`. Pasa a la 24 Paso 4.
